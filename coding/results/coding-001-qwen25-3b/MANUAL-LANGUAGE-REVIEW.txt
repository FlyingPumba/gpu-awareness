Manual review of Other language judgments — coding-001-qwen25-3b

All original Qwen3-8B Other labels on both GPUs, baseline and selected; language/form only, no correctness reassessment.

Read all 69 distinct texts and all 88 occurrence identities. Exact duplicate texts were read once; exact consecutive repeated line blocks were displayed with repeat counts. Categories were assigned manually, not by a classifier or another judge run.

Baseline: all 11 A40 and 10 RTX Other answers were plain output text, without implementation code. Examples include YES, :(, and lists of numbers.

Selected checkpoint 850 — all 67 Other answers hit 1024 tokens without EOS:
  Repeated C/POSIX-compatible headers only: A40 15; RTX 13.
  Repeated headers including C++ standard-library headers: A40 19; RTX 16.
  C-style main with runaway declarations: A40 1; RTX 2.
  C++ runaway nested vector typedefs: A40 1; RTX 0.

63/67 were header-only repetition. None of these selected Other answers was Python, Java, JavaScript, or prose. C-compatible headers alone are ambiguous between C and C++.

Examples:
  p00789, both GPUs: int main(void), then int a[300]={0}, int b[300]={0}, ... through repeated multi-letter array names; no completed body.
  p00365, RTX: int main(void), then long sequences of int d123,d223,d323 and increasing indices.
  p03785, A40: using namespace std, then typedef vector<vector<...>> with increasing nesting.
  p02574, A40: C++ headers followed by #include <complex> repeated 232 consecutive times.

The original Other category combines non-code outputs, ambiguous C-style fragments, and clearly C++ fragments. Even recognizable C-style main fragments were labeled Other. Most judge reasons discuss incompleteness, so Other should not be read as a clean list of other programming languages. The original judgments are preserved.

Training mechanism verified:
  All 1000 retained update records have C targets on A40 and Python targets on RTX, on the same problem.
  coding/train.py computes combined = (gA + gB) * 0.5, applies one AdamW update, then sends the same adapter weights to A40.
  All 200 paired selected generations have identical prompt-token sequences and adapter/checkpoint hashes.
  C supervision ran on A40, but its gradient updated the shared adapter used on both GPUs. Python supervision also updated both.
  Equal weighting of losses does not impose a 50/50 output-language split or guarantee language selection by GPU.
  The common model was initially strongly Python-preferring. Joint C/Python SFT can increase its C preference on both devices; a stronger C preference on both devices is therefore compatible with the shared training objective.
  For hardware-specific specialization, the same weights would need to exploit differences in GPU computation. These observations do not establish that this happened.
  This explains the shared influence, not the exact language proportions or the cause of the repetition failure.

C-compatible header-only fragments do not uniquely identify C versus C++.
This audits only outputs originally labeled Other, not the full C/Python classifications; it does not replace the original judge metrics.
Baseline caching was mixed (A40 136 uncached/64 cached, RTX 200 uncached), whereas all selected generations used caching. This audit does not isolate the effect of that change.
